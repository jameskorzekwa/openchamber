# Updates

How you update OpenChamber depends on how you installed it. In every case you can check your current version at **Settings → OpenChamber → About**.

## Desktop app

The desktop app checks for updates against GitHub releases. When one is available, OpenChamber tells you, downloads it when you choose, and installs it on the next restart. You're always in control — nothing installs without your say-so.

## Web and CLI

Public upstream installs use the installer or package manager that installed
OpenChamber. The update controls in **About** can handle that path, or you can
update with npm, pnpm, yarn, or Bun directly.

Validated J2K web artifacts use a separate GitHub Release channel. They do not
use npm or another package manager for updates. Target the running server:

```bash
openchamber update --port 3000
```

For a validated artifact, this command sends an authenticated local request and
returns once the server accepts the update. A systemd user service or another
supported restart-on-exit manager handles restart, exact-build attestation, and
rollback. The supported J2K headless target is Ubuntu x86_64 with Node 22.22.0
modules ABI 127, not generic Linux. Bun and npm are not required at runtime.

The J2K updater resolves canonical stable identity first, then selects the exact
target from its companion prerelease. Missing, duplicate, ambiguous, or
wrong-target artifacts stop before download. Schema 1 fallback is allowed only
for exact Darwin arm64 ABI 127.

Desktop signed delivery is separate and unchanged. These web channel rules do
not apply to the Desktop updater.

## The OpenCode server

OpenChamber and OpenCode update separately. When a new OpenCode version is available, OpenChamber offers to update it and restarts the server afterward. See [OpenCode Server](/opencode-server/) for how that server is managed.
